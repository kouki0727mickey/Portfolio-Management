# エンジニアポートフォリオサイト 設計メモ

## 目的
見た人に「このエンジニアに仕事を頼んでみたい」と思わせる。

## 制約
1. **AIが作ったと判断されないこと** — テンプレ的なレイアウト・配色・文言を避け、作者本人の手触り（手描き素材、実際の失敗談、具体的な数字、本人の言葉）で構成する。
2. **インタラクティブ性** — 読むだけでなく、触ると反応が返ってくる。
3. **エンターテイメント性** — 触っていて楽しい、見つけると嬉しい仕掛けがある。

## コンセプト：「作業机（The Workbench）」
トップページは真上から見たエンジニアの作業机。机の上の物をクリックすると、その物に対応するコンテンツが開く。

| 机の上の物 | 開くもの |
|---|---|
| ノート | 制作実績（プロジェクト一覧・詳細） |
| マグカップ | 自己紹介（どんな人か・働き方） |
| 工具箱 | スキル（できること・使ってきた道具） |
| 付箋の束 | 失敗談・学び（「やらかし帳」） |
| スマホ | 連絡先・仕事の相談 |
| 虫眼鏡 | ミニゲーム「バグ探し」 |

### インタラクション
- 机の物はホバーで少し持ち上がり、クリックで横からパネルが開く。URLは `#/projects` のように変わり、直リンク・戻るボタンが効く。
- `` ` ``（バッククォート）キーで隠しターミナルが開く。`help` `whoami` `ls` `open <名前>` `hire` などのコマンドでサイト内を操作できる。
- コナミコマンドで机の照明が落ち、カーソルがデスクライトになる「夜モード」。

### ミニゲーム「バグ探し」
短いコード片（10〜20行）が表示され、バグのある行をクリックして当てる。3問。当てると、作者が実際に現場で直した似たバグの話（1〜2行）が出る。制限時間なし、スコアは「何回目で当てたか」。腕前と考え方を遊びながら見せるのが狙い。

### 「AIっぽさ」を避けるルール
- 紫→ピンクのグラデーション、ガラス風カード、絵文字アイコン、ストックイラスト、3列カードのヒーローセクションを使わない。
- 素材は作者の手描きスキャン（SVG化）と実写写真を使う。
- 文章は作者本人が書く。禁止フレーズ（後述のリスト）を含む文章はビルド時のテストで落とす。
- 実績には必ず具体的な数字・期間・自分の担当範囲を書く。

### 仕事につなげる導線
- 画面右下に常に付箋「仕事の相談はこちら →」。クリックでスマホ（連絡先）パネル。
- ターミナルの `hire` コマンドで件名入りの mailto を開く。
- バグ探しを3問終えたら連絡先への誘導を出す。

### 範囲外（YAGNI）
CMS、問い合わせフォームのバックエンド、多言語対応、ブログ、アクセス解析。

### 既存ファイル
リポジトリ直下の `index.html`（リンク集ページ）はそのまま残す。新サイトは `portfolio/` に置く。
